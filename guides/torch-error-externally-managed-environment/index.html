pip install torch "error: externally-managed-environment" (tested)

pip install torch on Debian 12+/Ubuntu 23.04+ stops with error: externally-managed-environment, and --user fails the same way. Install PyTorch into a virtual environment instead, and use the CPU index if you have no NVIDIA GPU; reproduced and fixed below.

1. Reproduce: pip install torch on Debian's Python

run.sh runs in a fresh debian:trixie-slim container (Debian 13; Ubuntu 23.04+ behaves the same), installs the distro python3-pip, tries to install PyTorch system-wide, then installs it into a virtual environment:

#!/bin/sh
# Debian 13 (trixie), distro Python: install PyTorch
apt-get update -qq >/dev/null && apt-get install -y -qq python3-pip python3-venv >/dev/null 2>&1
python3 --version; pip --version | cut -d' ' -f1-2
echo '== 1. pip install torch'
pip install torch 2>&1 | head -4; echo "exit status: $(pip install torch >/dev/null 2>&1; echo $?)"
echo '== 2. sudo-less --user does not help'
pip install --user torch 2>&1 | head -1
echo '== 3. what apt offers'
apt-cache policy python3-torch | head -3
echo '== 4. venv + CPU-only wheel (dry run)'
python3 -m venv /opt/torch
/opt/torch/bin/pip install --dry-run torch --index-url https://download.pytorch.org/whl/cpu 2>&1 | grep '^Would install' | fold -s -w 100
echo '== 5. venv + default PyPI wheel (dry run)'
/opt/torch/bin/pip install --dry-run torch 2>&1 | grep '^Would install' | fold -s -w 100
echo '== 6. real install of the CPU wheel, then import'
/opt/torch/bin/pip install -q torch --index-url https://download.pytorch.org/whl/cpu 2>&1 | tail -1
/opt/torch/bin/python -c "import torch; print(torch.__version__, torch.tensor([1., 2.]).sum().item())"
du -sh /opt/torch | cut -f1

2. What it means

Debian marks its Python as externally managed (PEP 668), so pip refuses to install anything into it. pip install torch and pip install --user torch both stop with exit status 1 before a byte of PyTorch is downloaded. Nothing is wrong with torch; every package fails the same way (see pip "externally-managed-environment").

3. Fix: a venv, and pick the right wheel

  • python3 -m venv ~/torch-env (needs python3-venv), then ~/torch-env/bin/pip install torch. Inside the venv pip is no longer blocked.
  • No NVIDIA GPU? Use the CPU index: pip install torch --index-url https://download.pytorch.org/whl/cpu. Step 4 shows it pulls 10 packages and no CUDA libraries. The default PyPI wheel (step 5) also pulls cuda-toolkit, cuDNN, NCCL, triton and 18 nvidia-*/cuda-* packages. The CPU venv came to 899 MB on disk.
  • The CPU install printed Failed to initialize NumPy: No module named 'numpy' on import: torch does not depend on numpy, so add pip install numpy if you use .numpy() (see RuntimeError: Numpy is not available).
  • apt install python3-torch works without pip, but Debian 13 ships torch 2.6.0, well behind the 2.14.1 wheel on PyPI.
  • --break-system-packages silences the error but writes torch and its dependencies into the OS Python; prefer the venv.

Frequently asked questions

Why does pip install torch say externally-managed-environment?

Debian and Ubuntu mark the system Python as externally managed (PEP 668), so pip refuses to install any package into it, including with --user.

How do I install PyTorch on Debian or Ubuntu?

python3 -m venv ~/torch-env, then ~/torch-env/bin/pip install torch (add --index-url https://download.pytorch.org/whl/cpu for a CPU-only build).

Can I use apt install python3-torch?

Yes, it needs no pip, but Debian 13 packages torch 2.6.0, while PyPI has 2.14.1.
