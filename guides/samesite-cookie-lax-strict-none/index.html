SameSite cookies: Lax vs Strict vs None, tested in Chrome

We set one cookie per SameSite value and sent every common kind of cross-site request at it. This is what arrived.

1. What Chrome sent (request from another site)

Request from another siteLaxStrictNone; SecureNo SameSite
Link click (top-level GET)SentNot sentSentSent
Form POSTNot sentNot sentSentSent if set < 2 min ago, then not sent
fetch() with credentials: 'include'Not sentNot sentSentNot sent
iframeNot sentNot sentSentNot sent
ImageNot sentNot sentSentNot sent

Visiting the cookie's own site directly sent all of them.

2. Three things the table shows

  • No SameSite = Lax. Chrome stored the cookie as Lax. The one difference: for 2 minutes after it is set it still rides on cross-site POSTs (we saw it at once and not after 125 seconds). This keeps old POST-based sign-in flows working; don't rely on it.
  • SameSite=None without Secure is dropped. The cookie SameSite=None (no Secure) was never stored at all, so it was not sent even to its own site. Write SameSite=None; Secure and serve it over HTTPS.
  • Strict also blocks links. A user arriving from a search result or an email link to a Strict-cookie site looks logged out on that first page. Lax is the usual choice for session cookies; use Strict for cookies that only guard actions.

3. Which value to use

  • Session / login cookie on your own site: SameSite=Lax; Secure; HttpOnly.
  • Cookie that must work inside an iframe or in a fetch() from another site (embedded widgets, third-party APIs): SameSite=None; Secure. Browsers that block third-party cookies may still drop it.
  • Extra-sensitive actions (changing the password, payments): SameSite=Strict.
Set-Cookie: session=abc123; Path=/; Secure; HttpOnly; SameSite=Lax

"Cross-site" means a different registrable domain (plus scheme), not just a different origin: app.example.com and api.example.com are the same site, so SameSite does not separate them.

Frequently asked questions

What is the default SameSite value?

Lax. In our Chrome test a cookie with no SameSite attribute was stored as Lax and blocked on cross-site fetch, iframe and image requests.

Why is my SameSite=None cookie not set?

It needs Secure. In our test SameSite=None without Secure was rejected outright, while SameSite=None; Secure was stored and sent on every cross-site request.

Is a Lax cookie sent when the user clicks a link from another site?

Yes, on top-level GET navigation. Strict cookies were not sent on that click.

Does SameSite stop cross-site form POSTs?

Lax and Strict cookies were not sent on a cross-site POST. A cookie with no SameSite attribute was still sent during its first 2 minutes.
