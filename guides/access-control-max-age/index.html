Access-Control-Max-Age: default, 600 vs 86400, measured in Chrome

Access-Control-Max-Age says how many seconds the browser may reuse a CORS preflight (the OPTIONS request) before asking again. We counted the preflights Chrome sent.

1. Preflights for 4 PUTs at 0, 1, 4 and 7 seconds

Access-Control-Max-AgeOPTIONS requestsMeaning
(not sent)2Default 5 seconds: reused at 1 s and 4 s, expired by 7 s
04No caching: a preflight before every request
-14Same as 0
33Reused at 1 s, expired at 4 s and 7 s
6001One preflight for the whole run

2. Which value to send

  • Without the header, a busy single-page app makes a preflight round trip every 5 seconds per URL. That's the main thing this header fixes.
  • 600 (10 minutes) to 7200 (2 hours) is a sensible range. Chromium caps the value at 7200 and Firefox at 86400, so 86400 gives Chrome users 2 hours, not a day.
  • The cache is per page origin and exact request URL, so different paths or query strings each get their own preflight.
  • Keep it short while you are still changing the allowed methods or headers: browsers keep using the old preflight answer until it expires.
# nginx: answer preflights directly
if ($request_method = OPTIONS) {
    add_header Access-Control-Allow-Origin $cors_origin always;
    add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE" always;
    add_header Access-Control-Allow-Headers "Content-Type, Authorization" always;
    add_header Access-Control-Max-Age 7200 always;
    add_header Vary Origin always;
    return 204;
}

The $cors_origin allow-list map is in our multiple-origins CORS guide, and why Vary: Origin matters was measured separately. Why a JSON POST/PUT needs a preflight at all: Content-Type application/json.

Frequently asked questions

What is the default Access-Control-Max-Age?

5 seconds in Chrome. With no header, our test saw one preflight reused at 1 s and 4 s and a new one at 7 s.

Is Access-Control-Max-Age 86400 allowed?

Yes, but Chromium caps it at 7200 seconds (2 hours) and Firefox at 86400 (per their documentation).

How do I disable preflight caching?

Send 0 (or -1). In our test both caused a preflight before every request.

Why do I still see OPTIONS requests with a long max-age?

The cache is per URL and origin, so each new path or query string gets its own preflight. Also, DevTools with 'Disable cache' on skips it.
