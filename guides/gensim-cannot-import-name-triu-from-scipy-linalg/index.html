gensim: cannot import name 'triu' from 'scipy.linalg' (tested)

ImportError: cannot import name 'triu' from 'scipy.linalg' at import gensim means gensim 4.3.2 or older met SciPy 1.13 or newer, which removed triu. gensim 4.4.0 fixes it, and also fixes numpy.dtype size changed under NumPy 2. Tested below.

1. Reproduce: gensim 4.3.2 with a current SciPy

A fresh Python 3.11 venv and pip install gensim==4.3.2. Its metadata says only scipy>=1.7.0 and numpy>=1.18.5, so the resolver picks the newest of both. b1.py:

import numpy, scipy
print("numpy", numpy.__version__, "scipy", scipy.__version__)
import gensim
from gensim.models import Word2Vec
print("gensim", gensim.__version__)
sents = [["cat", "sat", "mat"], ["dog", "sat", "log"]] * 50
m = Word2Vec(sents, vector_size=8, min_count=1, seed=1, workers=1)
print(len(m.wv), "words in vocabulary")

scipy.linalg.triu (and tril) were removed in SciPy 1.13.0. With numpy 1.26.4, gensim 4.3.2 imported fine on SciPy 1.12.0 and failed with this exact error on SciPy 1.13.0. gensim 4.3.1 has the same uncapped metadata.

2. Fix: upgrade gensim, or pin scipy<1.13

$ pip install -U gensim
$ python b1.py
numpy 2.4.6 scipy 1.17.1
gensim 4.4.0
5 words in vocabulary

gensim 4.4.0 works with NumPy 2.4.6 and SciPy 1.17.1. It has wheels for Python 3.9 to 3.13. If you must keep 4.3.2:

$ pip install "scipy<1.13"
$ python b1.py
numpy 1.26.4 scipy 1.12.0
gensim 4.3.2
5 words in vocabulary

Pinning SciPy below 1.13 also pulled NumPy back to 1.26.4, because SciPy 1.12 does not support NumPy 2.

3. gensim 4.3.3 and NumPy 2: numpy.dtype size changed

gensim 4.3.3 fixed the triu import but pins numpy<2.0 and scipy<1.14.0. A clean install resolves to numpy 1.26.4 + scipy 1.13.1 and works. Asking for NumPy 2 alongside it is refused:

error: No solution found when resolving dependencies
  cause: Because gensim==4.3.3 depends on numpy>=1.18.5,<2.0 and you require gensim==4.3.3, we can conclude that you require numpy>=1.18.5,<2.0.
         And because you require numpy==2.2.6, we can conclude that your requirements are unsatisfiable.

Forcing numpy==2.2.6 in a second command (or any later install that upgrades NumPy) gives, exit code 1:

Restart any Jupyter kernel after changing versions. Same NumPy 2 problem elsewhere: SciPy, statsmodels, scikit-learn, PyArrow. All changes: NumPy 2 breaking changes.

Frequently asked questions

How do I fix cannot import name 'triu' from 'scipy.linalg' in gensim?

pip install -U gensim (4.4.0 worked with SciPy 1.17.1 and NumPy 2.4.6), or pin scipy<1.13 for gensim 4.3.2.

Which SciPy version removed triu?

SciPy 1.13.0. gensim 4.3.2 imported on SciPy 1.12.0 and failed on 1.13.0 in this test.

Does gensim support NumPy 2?

gensim 4.4.0 does. 4.3.3 pins numpy<2 and fails with numpy.dtype size changed if NumPy 2 is forced.
