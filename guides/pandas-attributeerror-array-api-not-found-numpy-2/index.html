AttributeError: _ARRAY_API not found / numpy.dtype size changed (pandas, NumPy 2)

AttributeError: _ARRAY_API not found and ValueError: numpy.dtype size changed both mean a compiled package built for NumPy 1.x was loaded under NumPy 2. With pandas 3 the culprit is often an old optional package such as bottleneck, and pandas still runs. Measured with real pip installs.

1. Old pandas + NumPy 2: "numpy.dtype size changed"

$ pip install -q "pandas==2.1.4" "numpy==1.26.4"
$ pip install -q "numpy==2.3.4"

pandas 2.1.4 requires numpy<2,>=1.23.2; python_version == "3.11", but you have numpy 2.3.4 which is incompatible.

pandas 2.1.4 declares numpy<2, yet pip installed NumPy 2.3.4 anyway: it printed an ERROR about the conflict but exited normally. The next import pandas fails because pandas' compiled parts were built against the NumPy 1 C layout (88 vs 96 bytes). The same thing happens when another package's requirements pull NumPy 2 in.

Here pandas 3.1.0 itself is fine. The banner and AttributeError: _ARRAY_API not found come from bottleneck 1.3.7, an optional speed-up pandas tries to import (see the import_optional_dependency("bottleneck", errors="warn") frame). pandas carries on without it: the script still printed 3 and exited with status 0. So the scary traceback is noise in this case, but the culprit is always the package in the last frame above the AttributeError, not pandas or NumPy. We got the same banner from numexpr 2.8.7 and scipy 1.11.4 (scipy then raised ImportError: numpy.core.multiarray failed to import and stopped).

3. Fix: upgrade the package named in the traceback

$ pip check
No broken requirements found.
$ pip install -q -U pandas bottleneck
$ pip check
No broken requirements found.
$ python -c "import numpy, pandas, bottleneck; print(numpy.__version__, pandas.__version__, bottleneck.__version__)"
2.3.4 3.1.0 1.6.0

pip check found nothing wrong, because bottleneck 1.3.7 does not declare a NumPy upper bound, so you cannot rely on it to spot this. Upgrading the package from the last traceback frame (here bottleneck, to 1.6.0) removed the banner. For case 1, upgrade pandas: 2.2.2 is the first release whose metadata allows NumPy 2 (2.2.1 still pins numpy<2). If you cannot upgrade the old package, do what the banner says and pin python -m pip install "numpy<2" in that environment.

Frequently asked questions

How do I fix AttributeError: _ARRAY_API not found?

Upgrade the package named in the last traceback frame above the error (for example bottleneck or numexpr). If you cannot, install numpy<2 in that environment.

What does numpy.dtype size changed, may indicate binary incompatibility mean?

A package (often an old pandas such as 2.1.x) was compiled against NumPy 1 and is being imported with NumPy 2. Upgrade pandas to 2.2.2 or later, or pin numpy<2.

Why didn't pip prevent the incompatible install?

pip reports the conflict as an ERROR line but still installs, and packages without an upper bound such as bottleneck 1.3.7 pass pip check.
