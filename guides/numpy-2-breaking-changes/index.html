NumPy 2 breaking changes: same code on 1.26 vs 2.x (tested)

The NumPy 2 changes that break most code: scalar repr is now np.float64(1.5), Python scalars no longer upcast (np.uint8(200) + 100 = 44), copy=False raises, and aliases like np.float_, np.NaN, np.in1d are gone.

One script, run unchanged under NumPy 1.26.4 (Python 3.11.17) and NumPy 2.5.4 (Python 3.13.5), shows the changes that break most code after upgrading. Each row prints the result, the exception, or the warning raised.

1. The same code on NumPy 1.26 and NumPy 2

import numpy as np
print("numpy", np.__version__)
checks = {
    "repr(np.float64(1.5))": lambda: repr(np.float64(1.5)),
    "np.float32(3) + 3.0 -> dtype": lambda: (np.float32(3) + 3.0).dtype,
    "np.uint8(200) + 100": lambda: np.uint8(200) + 100,
    "np.array([1, 2], copy=False) on a list": lambda: np.array([1, 2], copy=False),
    "np.float_": lambda: np.float_,
    "np.NaN": lambda: np.NaN,
    "np.in1d([1], [1])": lambda: np.in1d([1], [1]),
    "np.row_stack([[1], [2]]).shape": lambda: np.row_stack([[1], [2]]).shape,
}
import warnings
warnings.simplefilter("always")
for k, f in checks.items():
    with warnings.catch_warnings(record=True) as w:
        try:
            r = f()
        except Exception as e:
            r = f"{type(e).__name__}: {str(e).splitlines()[0][:90]}"
    extra = f"  [{w[0].category.__name__}]" if w else ""
    print(f"{k:42} {r}{extra}")

2. What changed, row by row

  • Scalar repr: repr(np.float64(1.5)) is now np.float64(1.5). This shows up in printed lists/dicts and breaks doctests and string comparisons; str() and print(x) are unchanged.
  • Type promotion (NEP 50): a Python scalar no longer upcasts a NumPy scalar. np.float32(3) + 3.0 stays float32, and np.uint8(200) + 100 wraps around to 44 with a RuntimeWarning instead of giving 300.
  • copy=False now means "never copy": np.array(list, copy=False) raises ValueError: Unable to avoid copy while creating an array as requested.
  • Removed aliases: np.float_ and np.NaN raise an AttributeError that names the replacement; np.Inf and np.bool8 are gone too. Details: numpy has no attribute int/float/bool8.
  • Removed functions with a plain has no attribute error in 2.5.4: np.in1d, np.row_stack.

3. Fixes that work on NumPy 2

import numpy as np
print("numpy", np.__version__)
x = np.float64(1.5)
print("repr:", repr(x), "| float():", float(x), "| str():", str(x))
np.set_printoptions(legacy="1.25")
print("legacy='1.25' repr:", repr(x))
np.set_printoptions(legacy=False)

print("np.asarray([1, 2]):", np.asarray([1, 2]))
print("np.isin([1, 3], [1]):", np.isin([1, 3], [1]))
print("np.vstack([[1], [2]]).shape:", np.vstack([[1], [2]]).shape)
print("np.uint8(200) + np.int64(100):", np.uint8(200) + np.int64(100))
print("np.float32(3) + np.float64(3.0) dtype:", (np.float32(3) + np.float64(3.0)).dtype)

Use float(x) / x.item() when you need plain Python values, or np.set_printoptions(legacy="1.25") to get the old repr while you migrate. Replace np.array(x, copy=False) with np.asarray(x), np.in1d with np.isin, np.row_stack with np.vstack. For promotion, make the other operand a NumPy scalar or array of the dtype you want (np.int64(100)) or cast first.

4. Import errors after upgrading

If the failure happens at import, it is a compiled package built for NumPy 1.x, not your code: numpy.dtype size changed, may indicate binary incompatibility and AttributeError: _ARRAY_API not found.

Frequently asked questions

Why does NumPy 2 print np.float64(1.5) instead of 1.5?

NumPy 2 changed scalar repr. str()/print are unchanged; use float(x), or np.set_printoptions(legacy='1.25') temporarily.

Why does np.array(x, copy=False) raise ValueError in NumPy 2?

copy=False now means never copy. Use np.asarray(x) to copy only when needed.

Why does np.uint8(200) + 100 give 44 in NumPy 2?

NEP 50: the Python int no longer upcasts the uint8, so the result overflows and wraps (with a RuntimeWarning). NumPy 1.26 gave 300.
