pip install numpy: error metadata-generation-failed (tested)

error: metadata-generation-failed when installing numpy means pip found no pre-built wheel for your Python version and tried to compile numpy from source, which failed (here: Unknown compiler(s)). Usually an old pinned numpy on a newer Python. Unpin or upgrade numpy, or use a Python version that numpy release has wheels for.

1. Reproduce it: an old pinned numpy on a new Python

echo '$ pip install numpy==1.26.4'
pip install --no-cache-dir --disable-pip-version-check --root-user-action=ignore numpy==1.26.4 2>&1 | tail -40

Read it from the bottom up. metadata-generation-failed only says that pip tried to build numpy from source and the build's first step failed. The real reason is inside the [20 lines of output] box: ERROR: Unknown compiler(s). pip downloaded the source archive because numpy 1.26.4 has no pre-built wheel for this Python version, and building numpy needs a C compiler (and more).

The usual trigger is a pinned old numpy in requirements.txt (often numpy==1.2x, or something that requires numpy<2) on a Python release newer than that numpy.

2. Which numpy versions have a wheel for your Python

A second fresh container, same image:

P="pip install --no-cache-dir --disable-pip-version-check --root-user-action=ignore"
echo '$ pip install --only-binary=:all: numpy==1.26.4'
$P --only-binary=:all: numpy==1.26.4 2>&1 | tail -3
echo
echo '$ pip install "numpy<2"'
$P "numpy<2" 2>&1 | grep -E "Downloading|metadata-generation|Unknown compiler" | head -3
echo
echo '$ pip install numpy'
$P numpy 2>&1 | grep -E "Downloading|Successfully"
python -c "import numpy; print('numpy', numpy.__version__)"

  • --only-binary=:all: forbids source builds, so pip prints the honest error instead: the list after from versions: is every numpy release that has a wheel for your Python and platform. Here that was only 2.5.2 to 2.5.4.
  • "numpy<2" picks 1.26.4, downloads numpy-1.26.4.tar.gz (a source archive, not a .whl) and fails the same way. A .tar.gz download line is the early warning.
  • Unpinned pip install numpy downloaded a cp315 wheel and installed in seconds. If your code works with a current numpy, loosen the pin; see numpy 2 breaking changes for what changed in 2.0.

3. If you really need the old numpy: use an older Python

Installing gcc, gfortran and BLAS so numpy 1.26 compiles is possible, but it is slow and an old numpy may simply not support the new Python's C API. Using a Python version that the old numpy shipped wheels for is faster. With uv (on the Linux host, Python 3.11 downloaded by uv):

$ uv venv -p 3.11 v311 && uv pip install -p v311/bin/python numpy==1.26.4
Using Python 3.11.17 environment at: v311
Downloading numpy (17.4MiB)
 Downloaded numpy
 + numpy==1.26.4
3.11.17 numpy 1.26.4 1

Python 3.11 got a pre-built numpy 1.26.4 wheel; nothing was compiled. In Docker, the same idea is FROM python:3.11-slim instead of python:3-slim.

The same metadata-generation-failed error appears for any package with C extensions (pandas, scipy, lxml, ...) when no wheel matches; the fix is the same: check --only-binary=:all:, loosen the pin, or use an older Python. Frequently asked questions

Why does pip install numpy fail with metadata-generation-failed?

pip found no wheel for your Python version (typically an old pinned numpy such as 1.26.4 on a newer Python), downloaded the .tar.gz source and the build failed, e.g. Unknown compiler(s) when no C compiler is installed.

How do I see which numpy versions have a wheel for my Python?

Run pip install --only-binary=:all: numpy==<your pin>. The error lists every version available as a wheel for your Python and platform after "from versions:".

How do I fix it?

Remove or loosen the numpy pin so pip picks a release with a wheel, or create the environment with an older Python (e.g. uv venv -p 3.11) that the pinned numpy shipped wheels for.
