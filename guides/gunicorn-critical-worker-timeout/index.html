gunicorn CRITICAL WORKER TIMEOUT (tested)

[CRITICAL] WORKER TIMEOUT (pid:...) means a gunicorn worker spent longer than --timeout (default 30 seconds) on one request, so the arbiter killed it and the client got a 500. Raise --timeout for legitimately slow requests, switch to -k gthread, or fix the slow call shown in the traceback.

1. Reproduce WORKER TIMEOUT

app.py, a WSGI app that sleeps for ?N seconds:

import time

def app(environ, start_response):
    secs = float(environ.get("QUERY_STRING") or 0)
    time.sleep(secs)                      # stands in for a slow DB call / model load
    start_response("200 OK", [("Content-Type", "text/plain")])
    return [f"slept {secs}s\n".encode()]

run.py starts gunicorn with different settings and sends one slow request each time:

2. What the log means

  • The default worker is sync and the default --timeout is 30 seconds (checked with gunicorn.config.Config().timeout). A sync worker that is busy with one request for longer than that is killed by the arbiter: [CRITICAL] WORKER TIMEOUT (pid:...).
  • The traceback ends in handle_abort / SystemExit: 1. Its middle frame is your code (app.py, line 5): that is where the request was stuck. Read it to find the slow call.
  • The client got HTTP 500 after the timeout (3.7s with --timeout 3), and the arbiter booted a replacement worker. Behind nginx this usually shows up as a 502.

3. Fixes

  • Raise the timeout if the slow request is legitimate: --timeout 10 let the 5-second request finish. The same setting in gunicorn.conf.py (timeout = 2 in the third trial) is picked up from the working directory without any flag.
  • Use threads: with -k gthread --threads 4 and --timeout 3, the 5-second request completed with no WORKER TIMEOUT in this test.
  • Fix the slow call (the frame in your code in the traceback): add a timeout to outbound HTTP/DB calls, or move long jobs to a task queue.
  • If workers time out at startup because the app loads a large model, load it lazily, or raise --timeout.

Frequently asked questions

What is the default gunicorn worker timeout?

30 seconds, with the sync worker class.

How do I increase the gunicorn timeout?

Pass --timeout 120 on the command line, or put timeout = 120 in gunicorn.conf.py in the working directory.

What does the client see on WORKER TIMEOUT?

In this test the client got HTTP 500 right after the timeout; through a reverse proxy it often appears as 502.
