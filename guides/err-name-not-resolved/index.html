ERR_NAME_NOT_RESOLVED / ENOTFOUND (tested)

net::ERR_NAME_NOT_RESOLVED (Chrome), getaddrinfo ENOTFOUND (Node.js), curl: (6) Could not resolve host and Python's gaierror all mean the same thing: DNS gave no IP address for the hostname. No connection was ever tried. We fed the same bad hostnames to four clients and wrote down exactly what each one reports.

1. What the error means

Before a client can connect, it turns the hostname into an IP address. If that step returns nothing, the request stops there. The server never sees it, so server logs, CORS settings and firewall rules are not involved.

There are two DNS answers that lead here. NXDOMAIN: the name does not exist. NODATA: the name exists but has no A or AAAA record (for example only a TXT record). Every client we tested reports both the same way, except Python, which tells them apart.

Compare ERR_CONNECTION_REFUSED / ECONNREFUSED: there the name resolved and the IP answered, but nothing was listening on the port.

What this shows:

  • A name that exists but has no address still fails. A TXT-only name gives the same ERR_NAME_NOT_RESOLVED, ENOTFOUND and curl exit 6 as a typo. Only Python (EAI_NODATA, -5) and Node's dns.resolve4 (ENODATA) say "the name exists, no address". Node's err.cause.errno also differs (-3007 vs -3008) while code stays ENOTFOUND.
  • AAAA-only names work on this box because it has IPv6. On a network without IPv6 they will resolve but fail at connect, which is a different error.
  • Underscores are not rejected by any client. They go to DNS and fail only if the record is missing.
  • A space is a URL error in Node and curl, not a DNS error. Chromium percent-encodes it and then fails DNS.
  • Labels over 63 characters are not caught by Chromium, Node or curl. They all report a plain DNS failure. Only Python's IDNA codec refuses them before DNS.
  • A trailing dot is fine. It just means "fully qualified".

4. ENOTFOUND vs EAI_AGAIN vs ESERVFAIL

ENOTFOUND means the resolver gave a definite answer: no address. A broken or unreachable resolver is different. We pointed a Node dns.Resolver at two fake DNS servers on 127.0.0.1 (system settings untouched):

  • Server that answers SERVFAIL: queryA ESERVFAIL example.com after 52 ms.
  • Server that never answers (timeout 1000 ms, 1 try): queryA ETIMEOUT example.com after 1001 ms.

For dns.lookup(), fetch() and most HTTP clients (they use getaddrinfo), a temporary resolver failure shows up as getaddrinfo EAI_AGAIN host (per the Node.js and glibc docs, not measured; we did not break the system resolver). EAI_AGAIN is worth a retry. ENOTFOUND usually is not: fix the name or the record.

5. How to fix it

  1. Copy the exact hostname from the error and check it with dig. NXDOMAIN means the name does not exist. NOERROR with no answer means a record is missing. 
    $ dig +short nonexistent-xyz.invalid A        # empty
$ dig nonexistent-xyz.invalid A | grep status
;; ->>HEADER<<- opcode: QUERY, status: NXDOMAIN
$ nslookup nonexistent-xyz.invalid
** server can't find nonexistent-xyz.invalid: NXDOMAIN
$ dig +short _dmarc.google.com A               # empty, but TXT exists
$ dig +short _dmarc.google.com TXT
"v=DMARC1; p=reject; ..."
  2. Check environment variables and config. An unset variable becomes the literal host undefined. We measured fetch(`http://${process.env.API_HOST}/`) with the variable unset: getaddrinfo ENOTFOUND undefined. A Docker service name used outside its compose network gives the same thing: getaddrinfo ENOTFOUND db.
  3. Check for a proxy. If the proxy hostname is wrong, curl says curl: (5) Could not resolve proxy: myproxy-typo.invalid (exit 5, not 6). Check HTTP_PROXY / HTTPS_PROXY.
  4. New domain or changed record? Resolvers cache answers, including negative ones, for the TTL. Query the authoritative server directly: dig @ns1.yourdns.com name A. If it answers there but not via your resolver, wait for the TTL.
  5. Browser cache. Chrome keeps its own host cache. Per Chrome's docs (not measured), chrome://net-internals/#dns has a "Clear host cache" button.
  6. Test without DNS to prove the server is fine. curl: --resolve host:port:ip. Chromium: --host-resolver-rules. We mapped nonexistent-xyz.invalid to a local server on 127.0.0.1:8983 this way and got 200, with Host: nonexistent-xyz.invalid sent as usual. 
    curl --resolve nonexistent-xyz.invalid:8983:127.0.0.1 http://nonexistent-xyz.invalid:8983/
chromium --host-resolver-rules="MAP nonexistent-xyz.invalid 127.0.0.1:8983"

Once the name resolves, the next errors are usually about the connection: ECONNREFUSED or ECONNRESET.

Frequently asked questions

Is ERR_NAME_NOT_RESOLVED a server problem?

No. The request never left the client. DNS gave no IP address for the hostname, so the server was never contacted. Check the hostname and its DNS records.

What is the difference between ENOTFOUND and EAI_AGAIN?

ENOTFOUND: the resolver answered that there is no address for the name. EAI_AGAIN: the resolver itself failed or timed out (per the Node.js docs). Retry EAI_AGAIN; fix the name or record for ENOTFOUND.

Why does fetch only say 'Failed to fetch'?

Browsers hide network details from JavaScript. In Chromium 153 a DNS failure gave TypeError: Failed to fetch, and the real cause, net::ERR_NAME_NOT_RESOLVED, was only in the console and DevTools.

My domain has a record but I still get ENOTFOUND. Why?

Check the record type. We tested a name with only a TXT record: Chromium, Node.js fetch and curl all failed as if it did not exist. Browsers and HTTP clients need an A or AAAA record.

Does curl exit code 6 always mean DNS?

Yes, exit 6 is 'Could not resolve host'. Exit 5 is the same failure for the proxy host. Exit 3 means the URL itself was rejected, as we saw with a space in the hostname.
