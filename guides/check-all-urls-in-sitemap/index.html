How to check every URL in a sitemap for errors

A sitemap should list only live, final URLs. Here is how to test every entry and what to do with the ones that fail.

1. A shell loop (small sitemaps)

curl -s --compressed https://www.sitemaps.org/sitemap.xml | grep -oE '<loc>[^<]+</loc>' | sed -E 's#</?loc>##g' |
while read -r url; do
  echo "$(curl -s -o /dev/null -w '%{http_code}' "$url") $url"
  sleep 0.5
done

Each line shows the HTTP status and the URL. Add | grep -v '^200' to see only problems. --compressed handles servers that send the file gzip-encoded. If the file is a sitemap index (its <loc> entries point to more sitemaps), run the loop on each child sitemap; a .xml.gz file needs | gunzip after curl.

2. What to do with each status

  • 200: fine.
  • 301 / 302 / 307 / 308: replace the entry with the final URL. Sitemaps should list only URLs that answer directly.
  • 404 / 410: remove the entry, or restore the page if it should exist.
  • 403 / 429 / 5xx: may be bot protection or rate limiting rather than a real problem. Recheck slowly, and check the page in a browser.

3. Large sitemaps

A sitemap can hold up to 50,000 URLs, and an index can point to many of them. At one request every half second, 50,000 URLs take about 7 hours. Run the checks in parallel, but gently, and watch for rate limiting.

Frequently asked questions

Why does Google Search Console report sitemap URLs as errors?

Usually because entries redirect, return 404, are blocked by robots.txt or carry noindex. Fix the sitemap so it lists only final, indexable URLs.

Should redirected URLs stay in the sitemap?

No. List the final URL the redirect points to.

Where is my sitemap?

Check https://your-site.com/robots.txt for a 'Sitemap:' line, or try /sitemap.xml and /sitemap_index.xml.
