cv2.imshow error: The function is not implemented (tested)

cv2.error: (-2:Unspecified error) The function is not implemented. Rebuild the library with Windows, GTK+ 2.x or Cocoa support from cv2.imshow() means the cv2 you import has no GUI backend: usually opencv-python-headless, often installed on top of opencv-python. Keep only one package and reinstall it, or save images with cv2.imwrite on headless machines.

1. Reproduce it: opencv-python-headless has no GUI

b1.py:

import cv2, numpy as np
print("cv2", cv2.__version__)
img = np.zeros((40, 60, 3), np.uint8)
for name, fn in [("imshow", lambda: cv2.imshow("win", img)),
                 ("waitKey", lambda: cv2.waitKey(1)),
                 ("namedWindow", lambda: cv2.namedWindow("win")),
                 ("destroyAllWindows", lambda: cv2.destroyAllWindows())]:
    try:
        r = fn()
        print(f"{name}: OK -> {r}")
    except cv2.error as ex:
        print(f"{name}:")
        for l in str(ex).splitlines():
            if l.strip():
                print("  " + l.strip())

  • Every window function (imshow, waitKey, namedWindow, destroyAllWindows) raises the same (-2:Unspecified error) The function is not implemented. Image processing (imread, cvtColor, resize, imwrite) still works.
  • The message tells you to install libgtk2.0-dev and re-run cmake. That only applies if you compile OpenCV yourself. With pip wheels, it means the installed cv2 was built without a GUI backend.

2. Check which build you actually import

b2.py:

import cv2, numpy as np, os
from importlib.metadata import version, PackageNotFoundError
for d in ("opencv-python", "opencv-python-headless"):
    try: print(d, version(d))
    except PackageNotFoundError: print(d, "not installed")
gui = [l.strip() for l in cv2.getBuildInformation().splitlines() if l.strip().startswith("GUI:")]
print(gui[0])
print("DISPLAY =", os.environ.get("DISPLAY"))

  • opencv-python and opencv-python-headless both install into the same cv2/ folder. Whichever was installed last wins: installing headless on top switched GUI: from QT5 to NONE, and imshow then fails as in section 1. This often happens silently when another package (e.g. a library that depends on opencv-python-headless) pulls the headless build in.
  • Uninstalling one of the two deletes shared files: afterwards import cv2 still "works" but the module is broken (module 'cv2' has no attribute '__version__').
  • The fix is to keep exactly one OpenCV package and reinstall it: pip uninstall -y opencv-python opencv-python-headless, then pip install opencv-python (or pip install --force-reinstall opencv-python as above). If you use contrib modules, the same rule applies to opencv-contrib-python vs opencv-contrib-python-headless.

On a machine with no screen, there is nothing to show a window on. Use the headless build and write images to files instead (next section), or connect with ssh -X / set DISPLAY to a real X server.

4. Headless-safe display: imwrite or matplotlib

b5.py:

import cv2, numpy as np

def has_gui():
    for line in cv2.getBuildInformation().splitlines():
        if line.strip().startswith("GUI:"):
            return line.split(":", 1)[1].strip() != "NONE"
    return False

def show(name, img):
    if has_gui():
        cv2.imshow(name, img)
        cv2.waitKey(0)
        cv2.destroyAllWindows()
    else:
        ok = cv2.imwrite(f"{name}.png", img)
        print(f"no GUI backend: wrote {name}.png ({ok})")

img = np.zeros((40, 60, 3), np.uint8)
img[:, :20] = (255, 0, 0)          # BGR: blue stripe
print("GUI backend available:", has_gui())
show("preview", img)

# Jupyter / matplotlib: convert BGR -> RGB first or blue shows as red
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
rgb = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
print("pixel BGR", img[0, 0].tolist(), "-> RGB", rgb[0, 0].tolist())
plt.imshow(rgb); plt.axis("off"); plt.savefig("preview_mpl.png")
print("saved preview_mpl.png")

Output (opencv-python-headless 5.0.0, matplotlib 3.11.2):

GUI backend available: False
no GUI backend: wrote preview.png (True)
pixel BGR [255, 0, 0] -> RGB [0, 0, 255]
saved preview_mpl.png
  • Read GUI: from cv2.getBuildInformation() to decide at runtime; fall back to cv2.imwrite(), which works in every build.
  • In Jupyter, use matplotlib.pyplot.imshow instead of cv2.imshow, and convert with cv2.COLOR_BGR2RGB first: OpenCV stores pixels as BGR, so a blue [255, 0, 0] pixel would otherwise display as red.

Frequently asked questions

Why does cv2.imshow say the function is not implemented?

The installed OpenCV build has no GUI backend (GUI: NONE in cv2.getBuildInformation()), typically opencv-python-headless.

I installed opencv-python but imshow still fails. Why?

opencv-python-headless is also installed and overwrote the cv2 folder. Uninstall both, then reinstall only opencv-python.

How do I show an image with OpenCV on a server or in Docker?

You cannot open a window without a display. Write it with cv2.imwrite, or use matplotlib (after BGR to RGB conversion) in Jupyter.
