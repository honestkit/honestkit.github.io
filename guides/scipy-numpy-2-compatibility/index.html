SciPy and NumPy 2 compatibility (tested)

SciPy 1.11 on NumPy 2 imports with a warning, then each submodule fails differently: numpy.core.multiarray failed to import, numpy.dtype size changed, or cannot import name 'Inf'. SciPy 1.13.0 is the first version that supports NumPy 2. Tested below.

1. Reproduce: SciPy 1.11.4 with NumPy 2

A Python 3.11 venv with scipy==1.11.4, then numpy==2.2.6 installed in a second command (asking for both in one command is refused by the resolver). b1.py:

import numpy
print("numpy", numpy.__version__)
import scipy
print("scipy", scipy.__version__)
from scipy import stats
print(stats.norm.cdf(1.96))

scipy.linalg and scipy.sparse also print the long "A module that was compiled using NumPy 1.x cannot be run in NumPy 2" banner plus AttributeError: _ARRAY_API not found before the ImportError. The dependency check spells out the conflict:

$ uv pip check
Found 1 incompatibility
The package `scipy` requires `numpy>=1.21.6,<1.28.0`, but `2.2.6` is installed

2. What the three errors mean

  • numpy.core.multiarray failed to import / _ARRAY_API not found (linalg, sparse): the extension module was compiled against the NumPy 1.x C API. See A module compiled using NumPy 1.x.
  • numpy.dtype size changed, may indicate binary incompatibility. Expected 96 from C header, got 88 (spatial, stats): a Cython module built against NumPy 1.x headers. Same root cause; see numpy.dtype size changed.
  • cannot import name 'Inf' from 'numpy' (optimize): pure Python code using an alias NumPy 2 removed (np.Inf, now only np.inf). See NumPy 2 breaking changes.

3. Which SciPy versions support NumPy 2

From the Requires-Dist metadata on PyPI. SciPy 1.13.0 is the first release that allows NumPy 2.

SciPyNumPy requirementNumPy 2 OK?
1.11.4numpy>=1.21.6, <1.28.0No
1.12.0numpy>=1.22.4, <1.29.0No
1.13.0 / 1.13.1numpy>=1.22.4, <2.3Yes (first)
1.14.1numpy>=1.23.5, <2.3Yes
1.15.3numpy>=1.23.5, <2.5Yes
1.16.0numpy>=1.25.2, <2.6Yes (Python 3.11+)
1.18.1numpy>=2.0.0, <2.8Yes (Python 3.12+, NumPy 2 only)

The upper bound matters too: SciPy 1.13 and 1.14 cap NumPy below 2.3, so a new NumPy can still outrun an old-but-NumPy-2-ready SciPy.

4. Fix: pin numpy<2, or upgrade SciPy

$ pip install "numpy<2"
$ python b1.py
numpy 1.26.4
scipy 1.11.4
0.9750021048517795
$ python b2.py
scipy.linalg    exit 0: OK
scipy.sparse    exit 0: OK
scipy.optimize  exit 0: OK
scipy.spatial   exit 0: OK
scipy.stats     exit 0: OK
$ pip install -U scipy numpy
$ python b1.py
numpy 2.4.6
scipy 1.17.1
0.9750021048517795
$ python b2.py
scipy.linalg    exit 0: OK
scipy.sparse    exit 0: OK
scipy.optimize  exit 0: OK
scipy.spatial   exit 0: OK
scipy.stats     exit 0: OK

On Python 3.11 the upgrade resolved to SciPy 1.17.1 with NumPy 2.4.6. If something else pins SciPy below 1.13 (an old scikit-learn, statsmodels or a lock file), use numpy<2 until you can upgrade it. Same problem in other libraries: scikit-learn, Matplotlib, OpenCV, TensorFlow, pandas.

Frequently asked questions

Which SciPy version supports NumPy 2?

SciPy 1.13.0 is the first release whose metadata allows NumPy 2 (numpy>=1.22.4,<2.3). SciPy 1.11 and 1.12 require numpy<1.28/<1.29.

How do I fix SciPy errors after upgrading to NumPy 2?

pip install "numpy<2", or pip install -U scipy numpy (scipy 1.17.1 + numpy 2.4.6 on Python 3.11 in this test).
