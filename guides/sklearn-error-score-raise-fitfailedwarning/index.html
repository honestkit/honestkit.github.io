sklearn error_score='raise' and FitFailedWarning (tested)

FitFailedWarning: ... If these failures are not expected, you can try to debug them by setting error_score='raise' means some cross-validation fits failed and were scored nan. Pass error_score='raise' to GridSearchCV or cross_val_score to stop at the first failure and see the original exception.

1. The FitFailedWarning that tells you to set error_score='raise'

b4.py:

import warnings, numpy as np
from sklearn.model_selection import GridSearchCV
from sklearn.linear_model import LogisticRegression
X = np.random.default_rng(0).normal(size=(60, 3))
y = (X[:, 0] > 0).astype(int)
grid = GridSearchCV(LogisticRegression(), {"C": [1.0, -1.0]}, cv=3)  # C must be > 0
with warnings.catch_warnings(record=True) as w:
    warnings.simplefilter("always")
    grid.fit(X, y)
for x in w:
    print(f"{x.category.__name__}: {x.message}")

  • By default (error_score=np.nan) a failing fit does not stop GridSearchCV: it records nan for that fold, emits one FitFailedWarning that groups identical errors (3 fits failed with the following error), and the search finishes.

2. Failures at scoring time look different

b1.py: the fit works but predict fails on the test fold:

import warnings, sklearn, numpy as np
from sklearn.model_selection import GridSearchCV
from sklearn.neighbors import KNeighborsClassifier

# cv=3 -> each training fold has 40 rows, so n_neighbors=50 cannot work

  • When the error happens while scoring, you get one UserWarning: Scoring failed per fold (3 here) instead of a grouped FitFailedWarning; both set the score to nan.
  • best_params_ silently ignores the nan candidate and picks n_neighbors=5. If every candidate fails, you get all-nan scores, so check cv_results_["mean_test_score"].

3. error_score='raise': stop at the first failure with a real traceback

b2.py:

import numpy as np
from sklearn.model_selection import GridSearchCV
from sklearn.neighbors import KNeighborsClassifier
X = np.random.default_rng(0).normal(size=(60, 3))
y = (X[:, 0] > 0).astype(int)
grid = GridSearchCV(KNeighborsClassifier(), {"n_neighbors": [5, 50]}, cv=3,
                    error_score="raise")
grid.fit(X, y)

Compare the three settings with cross_val_score (b3.py):

import warnings, numpy as np
from sklearn.model_selection import cross_val_score
from sklearn.neighbors import KNeighborsClassifier
warnings.simplefilter("ignore")
X = np.random.default_rng(0).normal(size=(60, 3))
y = (X[:, 0] > 0).astype(int)
knn = KNeighborsClassifier(n_neighbors=50)
print("default (nan):", cross_val_score(knn, X, y, cv=3))
print("error_score=0:", cross_val_score(knn, X, y, cv=3, error_score=0))
try:
    cross_val_score(knn, X, y, cv=3, error_score="raise")
except ValueError as ex:
    print("error_score='raise' -> ValueError:", ex)
default (nan): [nan nan nan]
error_score=0: [0 0 0]
error_score='raise' -> ValueError: Expected n_neighbors <= n_samples_fit, but n_neighbors = 50, n_samples_fit = 40, n_samples = 20
  • error_score='raise' re-raises the original exception, so you can use a debugger or %debug on it. Use it while developing; switch back to the default for long searches where a few bad combinations are expected.
  • error_score=0 replaces failures with 0 instead of nan. That hides the problem and drags the mean down rather than flagging it; prefer nan or 'raise'.
  • error_score is accepted by GridSearchCV, RandomizedSearchCV, cross_val_score, cross_validate and validation_curve/learning_curve.

Frequently asked questions

What does error_score='raise' do in sklearn?

It makes GridSearchCV, cross_val_score and friends re-raise the first exception from a failing fit or score, instead of recording nan and warning.

Why are my GridSearchCV mean_test_score values nan?

Those parameter combinations failed in fit or scoring. The FitFailedWarning or 'Scoring failed' UserWarning contains the cause; error_score='raise' shows it as a normal traceback.

Should I use error_score=0?

Usually not: it replaces failures with 0, which hides the error. Keep nan or use 'raise' while debugging.
