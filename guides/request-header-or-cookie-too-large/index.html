400 Bad Request: Request Header Or Cookie Too Large (nginx), fixed and tested

nginx shows this page when one request header line, almost always the Cookie line, is bigger than its buffer. We reproduced it with curl and with Chrome, then raised the limit.

1. What the error looks like

HTTP/1.1 400 Bad Request
Server: nginx/1.31.6
Content-Type: text/html
Content-Length: 233
Connection: close

<title>400 Request Header Or Cookie Too Large</title>
...<h1>400 Bad Request</h1>
Request Header Or Cookie Too Large

It comes from nginx itself, before your application runs, so your app logs show nothing.

2. What triggers it (default nginx, measured)

RequestResult
Cookie: a= + 8,180 bytes (line = 8,192 bytes with CRLF)200
Cookie: a= + 8,181 bytes400
7 cookies × 1,000 bytes on one Cookie line (7 KB)200
9 cookies × 1,000 bytes on one Cookie line (9 KB)400
4 separate header lines × 8,100 bytes (32.4 KB)200
32 separate header lines × 1,000 bytes200
33 separate header lines × 1,000 bytes400

The default is large_client_header_buffers 4 8k, which sets two limits: each header line (name, value and line ending) must fit in one 8 KB buffer, and all headers together in four of them, about 32 KB. A browser sends all cookies on one Cookie line, so it is the cookies' combined size that hits the 8 KB per-line limit, long before the 32 KB total. Many small cookies fail just like one big one.

3. Same thing in Chrome

Chrome refuses to store any single cookie whose name plus value exceeds 4,096 bytes: a 4,096-byte cookie was kept, a 4,097-byte one was silently dropped, whether it came from Set-Cookie or document.cookie. So one cookie can't cause this error; several can. With 4,000-byte cookies on the same host:

The page stays broken on every visit, because the browser keeps sending the same cookies until they expire or are deleted.

4. Fix it as a visitor

Delete the cookies for that one site; you don't need to clear everything. In Chrome: click the icon left of the address bar → Cookies and site data → Manage on-device site data → delete the site's entries, then reload. Or open DevTools → Application → Storage → Clear site data. A private window works too, because it starts with no cookies. If the error returns soon after, the site itself keeps setting too many cookies and only its owner can fix that.

5. Fix it as the server owner

Raise the buffers in the http or server block and reload:

large_client_header_buffers 4 16k;   # each line up to 16 KB, about 64 KB in total
nginx -t && nginx -s reload

Measured with 4 16k: a Cookie line with 16,372 bytes of value (16,384-byte line) passed and 16,373 failed; a 15 KB Cookie line that failed before now passed; 64 header lines of 1,000 bytes passed and 65 failed; a 40 KB Cookie line still failed. The per-line limit is the second number, so raise that one for cookie problems; raising only the count doesn't help: with 8 8k, 64 lines of 1,000 bytes passed but an 8,193-byte Cookie line still failed.

Then find the cause, or the next deploy will hit the new limit. Typical culprits are analytics and A/B-testing cookies piling up on a shared parent domain, sessions stored entirely in a cookie, and big JWTs (check one with the JWT decoder). If a CDN or load balancer sits in front, it has its own limit too. Node.js answers 431 instead of 400; limits for both servers are in HTTP header size limits, measured.

6. Reproduce it

curl -i -H "Cookie: a=$(head -c 9000 /dev/zero | tr '\0' a)" https://your-site/

A 400 with the text above means nginx refuses lines of that size. Over HTTP/2 nginx applies the same directive to header fields, per its documentation.

Frequently asked questions

How do I fix 400 Bad Request Request Header Or Cookie Too Large?

As a visitor, delete that one site's cookies (site info icon → Cookies and site data) and reload. As the site owner, raise large_client_header_buffers in nginx, e.g. 4 16k, and cut down the cookies the site sets.

What is the default large_client_header_buffers in nginx?

4 8k: each header line may be up to 8 KB and all of them together about 32 KB. In our test a Cookie line of 8,192 bytes passed and 8,193 bytes failed.

Why do I get this error in Chrome but not in another browser?

Cookies are stored per browser. The browser with the error has collected more cookies for that site; clearing them fixes it.

How big can a cookie be in Chrome?

4,096 bytes for name plus value. In our test a 4,097-byte cookie was silently dropped, from both Set-Cookie and document.cookie. Three 4,000-byte cookies were enough to trigger the nginx error.
